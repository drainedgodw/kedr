# Desktop preview validation

## Automated checks

The initial desktop preview contained 47 core tests, 14 workbench workflow tests
and 8 headless egui interaction tests: 69 total. The current revision has 79, as
recorded below. The initial tests cover Unicode editing, selection,
undo, desired-column navigation, CRLF/indentation, replace-all transactions, dirty
close guards, external-save refusal, workspace boundaries, fuzzy paths, cancellable
saved-file search, no-op dirty state, the tab limit, manifest checks and a real Cargo task against
an authored temporary fixture.

UI tests inject real egui events: typing, undo, IME preedit/commit, palette/modal
focus isolation, trust gating, unsaved-close preservation, long-line content
preservation and rendering fewer than 80 rows of a 100,000-line document. This is
not a timing benchmark or proof of native OS-level IME/accessibility correctness.

## Visual checks

`scripts/ui_capture.py` requests screenshots from the real eframe OpenGL native
window; it does not generate a separate HTML mock. Linux uses Xvfb plus Mesa software
rendering for local/CI captures. Generation validates PNG outputs and records the
binary SHA-256; a human/agent still must inspect each state for layout/readability.

```bash
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo build --locked --release -p kedr-studio
xvfb-run -a python3 scripts/ui_capture.py --binary target/release/kedr-studio
```

Local checks and observed remote results must be recorded separately. Stable CI
is configured for Linux, Windows and macOS, including model/UI tests and release
artifacts; only Linux performs native screenshots. Physical Arch/Wayland, Windows
and Mac interaction testing has not been performed here. There is no IDE-versus-
JetBrains benchmark and no claimed UI latency advantage.

Core 0.3 performance results refer to commit `b9967f04a2aa203dd0a123f951bf671d4afc4f6b`;
the desktop workspace changes Cargo manifests/lockfile but not the core source.
Do not substitute those historical microbenchmarks for Studio performance evidence.

## Catalog revision remote follow-up

Run `38297193260` at `cd0549d38bf6ed959d2dbafed0755268d4d5e8be` had one failed
job: macOS. The new synthetic dispatch test had hard-coded Windows/Linux Ctrl+Y
and Ctrl+Shift+N even though the implementation correctly selects macOS chords.
The test now obtains native DeleteLine and QuickOpen bindings from the registry,
so it checks each platform's actual preset rather than a different platform's
keys. Revised UI tests and Clippy pass locally; subsequent remote acceptance
remains dependent on the actual run result. No application binary change was
required for this test correction.

Run `38297565505` then exposed a genuine dispatch conflict: egui's default
`consume_key` ignores extra Shift/Alt, so Cmd+O intercepted Cmd+Shift+O.
The shell now consumes only exact modifier matches (with egui's platform command
normalization). An exhaustive regression test checks every registered chord in
both profiles and platform presets, including physical Ctrl/Command flags. This
also protects Undo/Redo and Save/Save-all from less-specific chord shadowing.
This correction changes application behavior and requires a rebuilt binary.

Exact-dispatch correction: all 80 workspace tests, warnings-denied Clippy and
optimized Linux rebuild pass locally. Remote macOS acceptance is still pending.

Follow-up CI investigation: the preceding redesign run passed all three desktop
jobs but failed the Arch package workspace tests. Recent-file matching used the
absolute checkout path, so `/tmp/kedr-package/src/kedr` introduced false fuzzy
matches. Matching now uses workspace-relative paths, consistent with quick-open;
the existing MRU test also rejects absolute-root queries. This is a correctness
fix, not evidence that the new hosted Arch package job has passed.

The first language CI run also found a Windows-only assertion mismatch between
a verbatim canonical path and its normal file-URI decoding. The URI round-trip
test now checks the canonical existing parent, the exact escaped filename and
the re-encoded URI; it does not require verbatim-prefix preservation. Runtime
target validation still canonicalizes the target before membership checks.
Windows execution of this correction awaits the subsequent hosted run.

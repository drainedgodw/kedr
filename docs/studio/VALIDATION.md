# Desktop preview validation

## Automated checks

The workspace contains the existing 47 core tests, 14 workbench workflow tests and
8 headless egui interaction tests: 69 total. These cover Unicode editing, selection,
undo, desired-column navigation, CRLF/indentation, replace-all transactions, dirty
close guards, external-save refusal, workspace boundaries, fuzzy paths, cancellable
saved-file search, no-op dirty state, the tab limit, manifest checks and a real Cargo task against
an authored temporary fixture.

UI tests inject real egui events: typing, undo, IME preedit/commit, palette/modal
focus isolation, trust gating, unsaved-close preservation, long-line content
preservation and rendering fewer than 80 rows of a 100,000-line document. This is
not a timing benchmark or proof of native OS-level IME/accessibility correctness.

## Visual checks

`scripts/ui_capture.py` requests screenshots from the real eframe OpenGL native
window; it does not generate a separate HTML mock. Linux uses Xvfb plus Mesa software
rendering for local/CI captures. Generation validates PNG outputs and records the
binary SHA-256; a human/agent still must inspect each state for layout/readability.

```bash
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo build --locked --release -p kedr-studio
xvfb-run -a python3 scripts/ui_capture.py --binary target/release/kedr-studio
```

Local checks and observed remote results must be recorded separately. Stable CI
is configured for Linux, Windows and macOS, including model/UI tests and release
artifacts; only Linux performs native screenshots. Physical Arch/Wayland, Windows
and Mac interaction testing has not been performed here. There is no IDE-versus-
JetBrains benchmark and no claimed UI latency advantage.

Core 0.3 performance results refer to commit `b9967f04a2aa203dd0a123f951bf671d4afc4f6b`;
the desktop workspace changes Cargo manifests/lockfile but not the core source.
Do not substitute those historical microbenchmarks for Studio performance evidence.

## Observed local result for the first preview

All 69 tests passed on Linux X11, Rust 1.99.0, x86_64, with two build workers.
`cargo fmt --all --check`, Clippy with warnings denied, documentation with warnings
denied, and the optimized Studio build passed. This is local evidence, not a
Windows/macOS or minimum-supported-Rust test result.

Eleven native capture scenes were inspected individually: dark/light editor,
900×640 compact editor, welcome, quick files, commands, settings, saved-project
search, unsaved-close decision, project trust and external-change error. Each
passed the preview layout/readability review at its captured size. Long code is
intentionally horizontally scrollable in the compact editor; search excerpts are
ellipsized with a full tooltip. During review, row spacing, left-aligned file
navigation, missing-font symbols, input target heights and search excerpts were
corrected. Screenshot evidence is generated by the shipped application, not a
separate UI mock. This review is not an accessibility or full platform acceptance
certification.

The local Linux archive is an unsigned x86_64 preview built on Amazon Linux 2023;
it is not a universal/AppImage package. Target-machine graphics/portal and glibc
compatibility still need checking. Remote platform results remain discoverable
in the Studio workflow and must be inspected rather than assumed.

## Observed first remote run

Studio run `38287015980` at commit
`8231ded38da1e35043d72405cd3e8088635991a9` passed tests, Clippy, release builds
and artifact uploads on Windows and macOS. Linux passed tests, Clippy and its
release build, but native capture failed before producing screenshots because
`libxkbcommon-x11.so` was missing from the runner. The workflow now installs
`libxkbcommon-x11-0`; the Arch guide also lists `libxkbcommon-x11`. This correction
is not itself evidence that a subsequent run succeeded. Physical Windows/macOS
interaction acceptance remains unperformed.
